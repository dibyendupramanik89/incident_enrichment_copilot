Request lifecycle
  1. User sends NL request via Gradio
  2. Gateway authenticates & injects trace-id
  3. Input guardrails validate & sanitise
  4. Orchestrator detects intent & plans
  5. MCP client discovers & calls tools
  6. Alarm API returns structured data
  7. RAG retrieves document evidence
  8. Output guardrails validate response
  9. HITL confirmation for write ops
  10. Grounded answer + citations returned
Key chaining flows (from Postman)
  • CHAIN-09 EastRefinery alarms → detail → priority → recommendations
  • CHAIN-01 Asset search → summary → rationalization
  • CHAIN-03 Compressor search → correlation → alarm → recommendations
  • CHAIN-02 Flood analysis → alarms in window → summary
  • CHAIN-10 Generate KPI calc → execute → rationalization
Design trade-offs
  • MCP vs direct call: all alarm ops through MCP only
  • Autonomy vs safety: write ops always need human confirm
  • Latency vs accuracy: cache + async for speed
  • RAG hallucination: grounding check + score threshold
  • Prompt injection: doc sanitisation before LLM
  • Cost vs quality: model-agnostic, swap LLM any time
Scaling strategies
  • Docker Compose → K8s horizontal scale
  • Async MCP tool invocation (asyncio)
  • Semantic cache (Redis + embeddings)
  • ChromaDB → Qdrant / Pinecone at scale
  • Agent pool with load balancing
  • Multi-region deployment ready
  • Model routing (mini → full on complexity)
